# P-Cloud OCR Agent 웹 UI 포트폴리오 및 프로젝트 구동 가이드

본 문서는 **`포트폴리오.html`** 웹 문서의 열람 방법 및 실제 **OCR Agent 웹 UI (Nuxt.js + Express.js)** 프로젝트 본체를 로컬/서버 환경에서 정상적으로 구동하기 위한 요구 파일과 실행 절차를 안내합니다.

---

## 1. 포트폴리오 HTML (`포트폴리오.html`) 열람 및 구동 안내

`포트폴리오.html`은 포트폴리오 열람자의 편의를 위해 **완전한 단독 실행형(Standalone Single File)**으로 제작되었습니다.

### ① 단독 실행 방법 (권장)
* **파일 위치:** `OCR_Agent_웹_UI_포트폴리오/포트폴리오.html`
* **실행 방법:** 파일 탐색기에서 **`포트폴리오.html`을 더블 클릭**하면 웹 브라우저(Chrome, Edge, Whale, Firefox, Safari 등)로 바로 열립니다.
* **이미지가 파일 안에 들어 있음:**
  * `screenshots/new/`의 1600×1000 스크린샷 12장이 HTML 파일 안에 Base64 데이터로 한 번씩 들어 있습니다(약 3.3MB).
  * 그래서 파일만 다른 위치로 옮기거나 메일로 보내도 이미지가 깨지지 않습니다. (글꼴은 인터넷에서 불러오므로, 오프라인에서는 기본 글꼴로 보입니다.)

### ② 주요 기능
1. **테마 전환 (Dark / Light):**
   * 상단 메뉴 오른쪽 `☀️ Light` / `🌙 Dark` 버튼으로 바꿀 수 있고, 고른 테마는 브라우저에 저장됩니다.
2. **화면 분류 탭:**
   * `전체`, `모니터링 · 통계`, `OCR · 배치`, `사용 기록 · 로그`, `로그인 · 설정 · 계정` 탭으로 화면을 골라 볼 수 있습니다. 괄호 안 개수는 카드 수로 자동 계산됩니다.
3. **이미지 크게 보기:**
   * 스크린샷을 누르면 원본 크기로 크게 보입니다.
   * `ESC` 키, 닫기 버튼, 바깥 어두운 영역을 누르면 닫힙니다.
4. **상세 화면 버튼:**
   * **02번(서버 모니터링):** `🖥️ Status 패널 보기 (02-1)` — Agent 동작 여부와 CPU·DISK·GPU 추이를 보여 주는 오른쪽 패널
   * **09번(계정 관리):** `👤 사용자 등록 창 보기 (09-1)` — 관리자 권한 체크와 비밀번호 입력이 있는 사용자 등록 창

### ③ 로컬 웹 서버로 열기 (선택 사항)
만약 로컬 HTTP 서버 환경에서 열람하고 싶다면 아래 명령어를 사용할 수 있습니다:
```bash
# Python 3 환경
python -m http.server 8000
# 브라우저 접속: http://localhost:8000/포트폴리오.html

# Node.js npx 환경
npx serve .
```

## 2. 실제 프로젝트 (Nuxt.js + Express.js) 본체 구동 가이드

본 웹 UI 애플리케이션을 로컬 개발 환경 또는 온프레미스 서버에서 직접 빌드하고 실행할 때 필요한 요구 파일 및 절차입니다.

### ① 필수 요구 파일 및 디렉토리 구조

```text
📁 agent_web_ui_bank1/
 ├── 📄 .env 또는 .env.local             [필수] MariaDB 접속 정보 및 JWT 시크릿 키
 ├── 📄 package.json                    [필수] 프로젝트 의존성 및 실행 스크립트 정의
 ├── 📄 nuxt.config.js                  [필수] Nuxt 프론트엔드 및 serverMiddleware 설정
 ├── 📁 server/
 │    ├── 📄 app.js                     [필수] Express 백엔드 진입점
 │    └── 📁 libs/
 │         ├── 📦 external_v4.1.2.jar   [필수] 금융/ActiveX SSO 라이브러리
 │         ├── 📦 INICrypto_v4.0.4.jar  [필수] SSO 티켓 암호화/복호화 모듈
 │         ├── 📦 log4j-1.2.8.jar       [필수] Java 로깅 라이브러리
 │         ├── 📦 servlet-api.jar       [필수] 서블릿 API
 │         ├── 📄 log4j.properties      [필수] 로깅 프로퍼티 설정
 │         ├── 📄 cookieManager.js      [필수] Java 서브프로세스 IPC 연동 모듈
 │         └── 📁 java-helper/
 │              └── 📄 CookieTicketReader.java [필수] 티켓 복호화 전담 Java 소스
 └── 📁 screenshots/
      └── 📁 new/                       [선택] 원본 1600×1000 고해상도 스크린샷 12종
```

### ② 필수 환경 설정 (`.env` 또는 `.env.local`)
루트 경로에 `.env` 또는 `.env.local` 파일을 생성하고 아래 항목들을 환경에 맞게 입력해야 합니다:

```ini
# MariaDB (MySQL 호환) 데이터베이스 접속 정보
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=your_db_user
MYSQL_PASSWORD=your_db_password
MYSQL_DATABASE=ocr_agent_db

# 최초 관리자 계정 정보
ACCOUNT=admin
ACCOUNT_PASSWORD=admin_password

# JWT 세션 시크릿 키
JWT_SecretKey=your_super_secret_jwt_key
JWT_S=your_secret_salt

# 호스트 및 에이전트 설정
STATIC_HOST=http://127.0.0.1:18020
BASE_URL=http://127.0.0.1:18020
AGENT_ID=agent_test_id
AGENT_KEY=agent_test_key

# SSO 모드 설정 (선택)
IBK=false
IBK_TEST=false
```

### ③ Java 런타임 (JDK 11) 환경 확인
* ActiveX SSO 티켓 복호화를 위해 **JDK 11**(JRE가 아닌 컴파일러 `javac`가 포함된 JDK)이 필요합니다.
* 기본 권장 설치 경로:
  ```text
  C:\Program Files\Java\jdk-11.0.2
  ```
* 다른 경로에 설치된 경우, `package.json`의 `scripts.dev`에 지정된 `JAVA_HOME` 및 `PATH` 설정을 맞추어야 합니다.

### ④ 의존성 설치 및 실행 명령어

#### 1) 패키지 의존성 설치
```bat
npm install
```

#### 2) 로컬 개발 서버 구동 (Development)
```bat
npm run dev
```
* **접속 주소:** `http://127.0.0.1:18020`
* `package.json`에 정의된 스크립트에 따라 JDK 11 경로와 `--openssl-legacy-provider` 플래그가 자동 주입되어 구동됩니다.

#### 3) 프로덕션 빌드 및 기동 (Production)
```bat
# 프로젝트 빌드
npm run build

# 프로덕션 서버 시작
npm run start

# 또는 PM2를 활용한 무중단 백그라운드 기동
pm2 start server/bin/www --name "ocr-agent-web-ui"
```

## 3. 핵심 구동 이슈 및 참고 사항

### ① Windows 예약 포트 충돌 (`listen EACCES`) 방지
* Windows OS(Hyper-V, WinNAT 등)의 Excluded Port Range 정책으로 인해 `8020`, `8080` 포트에서 `listen EACCES` 충돌이 발생할 수 있습니다.
* 본 프로젝트는 충돌 안전 지대인 **`18020`** 포트를 기본값으로 채택하고 있습니다.

### ② Node.js 상위 버전(17+) OpenSSL 3.0 호환성
* 최신 Node.js 환경에서 레거시 암호화 모듈 로딩 시 `digital envelope routines::unsupported` 에러가 발생하지 않도록, 개발/시작 스크립트에 `NODE_OPTIONS=--openssl-legacy-provider`가 기본 포함되어 있습니다.

### ③ Java SSO 헬퍼 프로세스 격리 구조
* SSO 복호화는 Node.js 메인 프로세스 내부에서 직접 네이티브 호출을 하지 않고, `child_process.spawnSync` 기반의 **독립 Java 헬퍼 프로세스(`CookieTicketReader.java`)**로 분리되어 안전하게 실행됩니다.
* 구동 시 필수 JAR 파일들을 순수 ASCII 임시 폴더(`os.tmpdir()/agent-web-ui-java-libs`)로 자동 캐싱 복사하여 윈도우 한글 경로에서도 에러 없이 완벽 구동됩니다.
