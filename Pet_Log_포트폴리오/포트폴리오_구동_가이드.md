# 🐾 Pet Log 포트폴리오 및 프로젝트 구동 가이드

이 문서는 **Pet Log(펫로그) 포트폴리오 HTML 파일을 여는 방법**과 **실제 서비스 프로젝트(프론트엔드·백엔드)를 로컬에서 실행하고 검증하는 방법**을 안내합니다.

---

## 1. 포트폴리오 HTML 여는 방법

---

### 1.2 실행 방법

#### 방법 1: 파일 더블클릭 (가장 간단)
- 파일 탐색기에서 `Pet_Log_포트폴리오/포트폴리오.html`을 **더블클릭**합니다.
- Chrome, Edge, Safari, Firefox 등 최신 브라우저에서 바로 열립니다.
- 인터넷 연결이 없어도 레이아웃, 다크 모드, 이미지 확대 보기가 동작합니다.

#### 방법 2: 로컬 웹 서버로 열기
`Pet_Log_포트폴리오/` 폴더에서 아래 명령 중 하나를 실행합니다.

```bash
# Python 3 내장 웹 서버 (포트 8000)
python -m http.server 8000
# 접속 주소: http://localhost:8000/포트폴리오.html
```

```bash
# Node.js (npx serve)
npx serve .
# 접속 주소: http://localhost:3000/포트폴리오.html
```

## 2. Pet Log 실제 프로젝트 실행 방법

Pet Log는 **Next.js 16 프론트엔드**와 **FastAPI + LangGraph 기반 Python AI 백엔드**로 구성되어 있습니다.

### 2.1 필요한 환경
- **Node.js**: 20.9 이상 (Next.js 16 요구사항)
- **Python**: 3.12 이상
- **Python 패키지 관리자**: `uv`
- **로컬 LLM 런타임 (선택)**: Ollama

---

### 2.2 프론트엔드 (Next.js) 실행 및 검증

#### 1) 폴더 이동 및 의존성 설치
```bash
cd frontend/app/web
npm install
```

#### 2) 환경변수 설정
`npm run dev`는 `.env.dev` 파일을 읽습니다. 예시 파일을 복사해서 만듭니다.
```bash
cp .env.example .env.dev
```
- 주요 설정 항목:
  - `PET_LOG_BACKEND_API_BASE_URL`: 백엔드 주소 (기본값 `http://127.0.0.1:27893`)
  - `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`: 동물병원 지도 표시용 Google Maps API 키 (없으면 지도 대신 안내 문구 표시)
  - `PET_LOG_AI_PROVIDER` (선택): `mock`(기본값) 또는 `openai`
  - `OPENAI_API_KEY` (선택): `PET_LOG_AI_PROVIDER=openai`일 때 필요

#### 3) 개발 서버 실행
```bash
npm run dev
```
- 접속 주소: **http://localhost:3000**
- Next.js Route Handler(`/api/v1/...`)가 요청을 FastAPI 백엔드로 전달합니다. 백엔드가 꺼져 있으면 Mock 데이터로 화면이 동작합니다.

#### 4) 테스트 및 정적 검사
```bash
# 단위 테스트 (스프린트 01~19 테스트 포함)
npm test

# 린트
npm run lint

# TypeScript 타입 검사
npm run typecheck

# 프로덕션 빌드
npm run build

# Playwright 모바일 화면 점검 + 기록 입력 E2E (최초 1회 npx playwright install 필요)
npm run eval
```

---

### 2.3 백엔드 (FastAPI & AI Agent) 실행 및 검증

#### 1) 폴더 이동 및 환경변수 설정
```bash
cd backend
cp .env.example .env
```

주요 환경변수 (`backend/.env.example` 기준):
```ini
# 로컬 Gemma (Ollama)
LLM_EAGER_LOAD=1
LOCAL_LLM_AUTOSTART=1          # 서버 시작 시 ollama serve 자동 실행
LOCAL_LLM_RUNTIME=ollama
GEMMA_AUTO_PULL=1              # 모델이 없으면 자동 다운로드
GEMMA_PRELOAD=1                # 서버 시작 시 모델을 메모리에 미리 올림
GEMMA_MODEL=gemma4:e4b

# OpenAI (기능별 모델)
OPENAI_API_KEY=your_openai_api_key
OPENAI_RECORD_STRUCTURING_MODEL=gpt-5-mini
OPENAI_RECORD_STRUCTURING_FALLBACK_MODEL=gpt-5-nano
OPENAI_SHOPPING_REASON_MODEL=gpt-5-mini
OPENAI_SHOPPING_REASON_FALLBACK_MODEL=gemma4:e4b

# 예비 모델 (설정 시 fallback 체인에 자동 추가)
GEMINI_API_KEY=your_gemini_api_key

# 외부 API
NAVER_SHOPPING_CLIENT_ID=your_naver_id
NAVER_SHOPPING_CLIENT_SECRET=your_naver_secret
GOOGLE_MAPS_API_KEY=your_google_maps_key
TAVILY_API_KEY=                # 케어 지식 수집(RAG)용, 선택
```

> [!NOTE]
> 모델 호출 순서는 **기능별 모델(`OPENAI_*_MODEL`) → 기능별 예비 모델(`OPENAI_*_FALLBACK_MODEL`) → Gemini → 로컬 Gemma** 입니다. 타임아웃·호출 한도 초과·서버 오류일 때 다음 모델로 넘어갑니다.
> 로컬 Gemma를 기본 모델로 쓰려면 `OPENAI_*_MODEL` 값을 `gemma4:e4b`로 바꾸면 됩니다.
> API 키가 없어도 서버는 실행되며, 병원·쇼핑 추천은 대체 결과(검색 링크 등)를 보여줍니다.

#### 2) 백엔드 개발 서버 실행

**Windows:**
```cmd
scripts\run-dev.bat
```

**macOS / Linux:**
```bash
./scripts/run-dev.sh
```

**또는 `uv`로 직접 실행:**
```bash
uv run uvicorn main:app --reload --host 127.0.0.1 --port 27893
```
- 백엔드 API 주소: **http://127.0.0.1:27893**
- Swagger API 문서: **http://127.0.0.1:27893/docs**
- 포트는 `PET_LOG_BACKEND_PORT` 환경변수로 바꿀 수 있습니다. 바꾸면 프론트엔드의 `PET_LOG_BACKEND_API_BASE_URL`도 같이 맞춥니다.

#### 3) 테스트 및 계층 규칙 검사
```bash
# 전체 단위·통합 테스트
uv run python -B -m unittest discover -s tests -v

# 패키지 import 확인
uv run python -B -c "import application, agent_runtime, middleware, tools, infrastructure, presentation, composition; print('target imports ok')"

# 계층 규칙 검사: application·domain 계층에 FastAPI, OpenAI SDK, DB 드라이버 import가 없어야 함
# (출력이 없으면 정상)
rg -n "fastapi|openai|sqlalchemy|sqlite|postgres|psycopg" src/application src/domain
```
