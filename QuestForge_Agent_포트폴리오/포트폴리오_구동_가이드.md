# QuestForge Agent — 포트폴리오 보기 및 프로젝트 실행 가이드

이 문서는 `포트폴리오.html`을 여는 방법과, 포트폴리오에서 설명한 QuestForge Agent(FastAPI 백엔드 + LangGraph 파이프라인 + React Quest Lab)를 직접 실행해 보는 방법을 안내합니다.

## 2. `포트폴리오.html` 보기

설치나 빌드 없이 브라우저로 바로 열 수 있습니다. 단, `screenshots/` 폴더가 **같은 위치에 있어야** 이미지가 나옵니다.

### 방법 A. 더블 클릭 (권장)
파일 탐색기에서 `포트폴리오.html`을 더블 클릭하면 Chrome·Edge 등 기본 브라우저에서 열립니다.

### 방법 B. 로컬 웹 서버로 열기 (선택)
```powershell
# QuestForge_Agent_포트폴리오 폴더에서 실행
python -m http.server 8080
```
브라우저에서 `http://localhost:8080/포트폴리오.html` 접속

### 방법 C. PDF로 저장
브라우저에서 `Ctrl + P` → 대상 **PDF로 저장**. 인쇄용 스타일이 적용되어 상단 메뉴가 숨겨지고 흰 배경으로 출력되며, 탭으로 나뉜 코드 예시도 모두 펼쳐집니다.

> 참고: 글꼴(Pretendard, JetBrains Mono)은 CDN에서 불러옵니다. 인터넷이 없으면 시스템 기본 글꼴로 표시되지만 내용은 그대로 보입니다.

## 3. 프로젝트 실행

### 준비물
- Python 3.12와 [uv](https://docs.astral.sh/uv/)
- Node.js (npm) — 저장소의 프론트엔드 스크립트는 pnpm을 사용합니다. pnpm이 없으면 아래처럼 npm으로 실행해도 됩니다.
- LLM 하나: 로컬 [Ollama](https://ollama.com/) 또는 OpenAI / Gemini API 키

### 3-1. LLM 설정 (필수)

퀘스트를 실제로 생성하려면 LLM 설정이 필요합니다. **처음에 어떤 Agent가 처리할지 고르는 라우팅 단계가 LLM을 사용하기 때문**입니다. LLM 설정이 없으면(`none`) 요청은 `ROUTING_UNAVAILABLE` 오류로 끝납니다.

로컬 Ollama를 쓰는 경우(포트폴리오 스크린샷도 이 방식으로 찍었습니다):

```powershell
ollama pull gemma4:e2b
copy backend\.env.example backend\.env
```

`backend\.env.example`의 기본값이 `local` / `gemma4:e2b` / `http://localhost:11434/v1`입니다. OpenAI나 Gemini를 쓰려면 `backend\.env.prod.openai.example` 또는 `backend\.env.prod.gemini.example`을 복사해 키를 넣고 `scripts\backend-prod-openai.cmd`, `scripts\backend-prod-gemini.cmd`로 실행합니다.

### 3-2. 의존성 설치

```powershell
scripts\backend-install.cmd
cd frontend; npm install; cd ..
```
(pnpm이 있으면 `scripts\frontend-install.cmd`도 사용할 수 있습니다.)

### 3-3. 실행 방법 1: 빌드 후 한 포트로 실행 (권장)

프론트엔드를 빌드하면 백엔드가 `frontend\dist`를 함께 서빙해서, 18000번 포트 하나로 화면과 WebSocket을 모두 사용할 수 있습니다.

```powershell
cd frontend; npm run build; cd ..
scripts\backend-dev.cmd 18000
```
(pnpm이 있으면 `scripts\serve-built-app.cmd 18000` 한 번으로 빌드와 실행을 같이 합니다.)

접속 주소:
- Quest Lab: `http://127.0.0.1:18000/`
- Health check: `http://127.0.0.1:18000/health`
- WebSocket: `ws://127.0.0.1:18000/ws/agent`

Quest Lab에서 **퀘스트 생성**을 누르면 됩니다. 로컬 gemma4:e2b 기준으로 한 번에 15~20초 정도 걸렸습니다.

### 3-4. 실행 방법 2: 백엔드와 프론트엔드 개발 서버를 따로 실행

```powershell
scripts\backend-dev.cmd 18000
```
새 터미널에서:
```powershell
cd frontend; npm run dev -- --port 5173
```
`http://127.0.0.1:5173/`에 접속합니다. Vite 프록시는 없고, Quest Lab 화면의 **WebSocket URL** 입력칸(기본값 `ws://127.0.0.1:18000/ws/agent`)으로 백엔드에 직접 연결합니다.
(pnpm이 있으면 `scripts\dev-all.cmd`가 두 서버를 각각 새 창으로 띄웁니다.)

### 3-5. LLM 없이 하는 스모크 점검

```powershell
scripts\backend-smoke-none.cmd
```
백엔드 서버가 켜져 있어야 합니다. 이 점검은 **퀘스트를 생성하지 않고**, 헬스 체크·잘못된 JSON·잘못된 메시지 형식·`ROUTING_UNAVAILABLE` 같은 **오류 경로가 정상적으로 응답하는지**만 확인합니다.

## 4. 테스트 실행

```powershell
# 백엔드 전체 테스트 (244개, LLM 없이 StubLLM으로 실행)
scripts\backend-test.cmd

# 프론트엔드 테스트 (36개) 와 빌드
cd frontend; npm test; npm run build; cd ..
```

`scripts\test-all.cmd`는 백엔드 **계약 테스트**와 프론트엔드 테스트를 이어서 실행합니다(프론트엔드 부분은 pnpm 필요).

2026-11-14 확인 결과: 백엔드 244 passed, 프론트엔드 36 passed, 프론트엔드 빌드 성공.
